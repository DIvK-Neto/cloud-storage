## Цели проекта

Проект создаётся как **готовый к использованию продукт**, а не как прототип. Основные цели:

1. Полноценное веб-приложение с бэкендом на Django и фронтендом на React.
2. Лёгкость развёртывания (инструкция для reg.ru и локальной разработки).
3. Модульность и масштабируемость.
4. Безопасность и чистота кода.

---

## Структура проекта (три уровня)

Проект состоит из трёх независимых частей, каждая из которых может жить отдельно:

### 1. Главная часть (корень проекта)
Содержит:
- `README.md` — общее описание проекта, ссылки на бэкенд и фронтенд.
- `docs/` — общая документация (установка, деплой, архитектура, технологический стек).
- `.github/` — общие CI/CD настройки (если они общие).
- `.gitignore`, `.env.example` и другие общие файлы.

**Назначение:** объединяет проект, даёт общее понимание и инструкции для разработчика.

### 2. Бэкенд (`backend/`)
Содержит:
- Django-приложения, API, модели, логику.
- Собственную документацию в `backend/docs/`.
- Собственный `requirements.txt`.
- Собственный `README.md`.

**Назначение:** реализует бизнес-логику и предоставляет REST API.

### 3. Фронтенд (`frontend/`)
Содержит:
- React-приложение, Redux, маршрутизацию.
- Собственную документацию в `frontend/docs/`.
- Собственный `package.json`.
- Собственный `README.md`.

**Назначение:** пользовательский интерфейс, взаимодействие с API.

## Модульность и масштабируемость

- **Модульность**: код разделён на приложения (`accounts_app`, `files_app`, `logs_app`), общие компоненты вынесены в `core/`.
- **Расширяемость**: новые функции добавляются через новые приложения или модули без изменения существующего кода.
- **Конфигурация**: все настройки вынесены в переменные окружения (`.env`).

---

## Возможность разделения на независимые репозитории

Проект спроектирован так, что **каждая из трёх частей может быть вынесена в отдельный репозиторий** без изменения кода:

- Главная часть → репозиторий с документацией и общими настройками.
- Бэкенд → репозиторий с Django-приложением.
- Фронтенд → репозиторий с React-приложением.

Для разделения достаточно скопировать соответствующие папки в новые репозитории и настроить для них отдельные CI/CD. Все ссылки в документации и коде используют относительные пути, что упрощает перенос.
